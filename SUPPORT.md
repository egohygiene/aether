# Support

## Getting help

- Read `README.md` for setup, validation, install, and release basics.
- Use repository issues for bugs, documentation fixes, and feature requests.
- For security issues, use `SECURITY.md` reporting guidance instead of public disclosure.

## What to include in support requests

- exact command(s) run;
- full output/error text;
- repository ref/commit;
- whether the issue is in canonical source (`library/organization/`) or generated output (`dist/`, `catalog/...`).

## Ownership boundaries

If your request is about CI workflow orchestration, org deployment, template bootstrapping, or conformance systems, route to the owning neighbor repository/system identified in `README.md` and `PURPOSE.md`.
